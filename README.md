# SupportFlow

SupportFlow는 고객 문의를 접수하고, 지원팀이 처리 우선순위를 판단하며, AI가 운영 맥락을 정리해주는 고객지원 운영 대시보드입니다.

고객은 문의를 남기고 답변을 확인합니다. 상담원은 배정된 문의를 처리하고 고객 답변과 내부 메모를 구분해 남깁니다. 관리자는 전체 문의 흐름, 담당자 배정, 응답 위험, AI 검토가 필요한 항목을 한 화면에서 확인합니다.

배포: https://support-flow-five.vercel.app/

## 제품 개요

SupportFlow는 단순 문의 게시판이 아니라 실제 지원팀의 업무 흐름을 기준으로 구성된 운영 SaaS입니다.

- 문의 접수부터 답변 완료까지의 상태를 관리합니다.
- 고객, 상담원, 관리자 역할에 따라 볼 수 있는 정보가 다릅니다.
- 고객 공개 답변과 내부 메모를 분리합니다.
- 담당자, 우선순위, 상태, 카테고리, AI 위험 신호를 한 목록에서 확인합니다.
- AI가 문의 요약, 감정, 긴급도, 답변 초안을 제안합니다.
- AI가 만든 내용은 바로 고객에게 발송되지 않고 사람이 검토합니다.
- 위험하거나 신뢰도가 낮은 AI 판단은 운영자가 먼저 확인할 수 있게 표시합니다.

## 해결하려는 문제

고객지원팀은 문의가 많아질수록 단순히 답변 속도만 관리해서는 운영 품질을 유지하기 어렵습니다.

SupportFlow는 다음 문제를 줄이는 데 초점을 둡니다.

- 지금 먼저 봐야 하는 문의를 빠르게 찾기 어렵습니다.
- 환불, 결제, 보안, 부정 감정 같은 위험 신호를 놓치기 쉽습니다.
- 고객에게 보여도 되는 답변과 내부 공유용 메모가 섞이면 운영 사고가 날 수 있습니다.
- 상담원과 관리자의 권한과 책임 범위가 분리되어야 합니다.
- AI가 도움을 주더라도 최종 판단은 사람이 해야 합니다.

## 사용자 역할

| 역할 | 목적 | 주요 작업 |
| --- | --- | --- |
| 고객 | 문의를 남기고 답변을 확인 | 문의 등록, 내 문의 조회, 공개 답변 확인 |
| 상담원 | 배정된 문의를 처리 | 상태 변경, 고객 답변, 내부 메모, AI 분석 확인 |
| 관리자 | 전체 지원 운영을 관리 | 전체 문의 조회, 담당자 배정, 우선순위 조정, 운영 지표 확인 |

고객에게는 AI 분석, 내부 메모, 활동 로그, 담당자 운영 정보가 노출되지 않습니다.

## 주요 화면

### 공개 홈

제품의 핵심 흐름을 실제 화면 캡처 중심으로 보여주는 랜딩 페이지입니다. 문의 목록, AI 보조 패널, 운영 리포트 화면을 통해 SupportFlow가 어떤 제품인지 빠르게 파악할 수 있습니다.

### 문의함

지원팀이 가장 자주 보는 화면입니다. 문의 상태, 우선순위, 담당자, 태그, AI 신호, 업데이트 시간을 한 목록에서 확인합니다. 검색과 필터를 통해 답변 대기, 부정 감정, 긴급 문의를 빠르게 찾을 수 있습니다.

### 문의 상세

문의 내용, 공개 답변, 내부 메모, 상태 변경, 담당자 배정, 활동 흐름을 확인합니다. 상담원과 관리자는 오른쪽 AI 어시스턴트에서 문의 요약과 답변 초안을 참고할 수 있습니다.

### AI 검토

AI가 낮은 신뢰도나 위험 신호를 감지한 문의를 모아 보여줍니다. 운영자는 이 화면에서 놓치기 쉬운 긴급 문의나 부정 감정 문의를 먼저 확인할 수 있습니다.

### 운영 대시보드와 리포트

실제 문의 데이터로 답변 대기 건수, 처리 상태, 담당자 부하, 카테고리 분포를 확인합니다. 지원팀의 병목과 운영 품질을 한눈에 점검하기 위한 화면입니다.

## AI가 돕는 방식

SupportFlow의 AI는 상담원을 대체하지 않습니다. 문의를 더 빨리 이해하고 우선순위를 판단할 수 있도록 돕는 보조 역할입니다.

AI는 다음 정보를 제안합니다.

- 문의 요약
- 카테고리
- 감정
- 긴급도
- 고객 의도
- 추천 우선순위
- 추천 상태
- 답변 초안
- 검토 필요 여부

답변 초안은 자동 발송되지 않습니다. 상담원이 직접 확인한 뒤 답변 작성란에 불러와 수정하고 제출합니다.

## 데모에서 볼 수 있는 흐름

1. 고객 계정으로 문의를 등록합니다.
2. 관리자 또는 상담원 계정으로 문의함에서 새 문의를 확인합니다.
3. 자동 분석이 설정되어 있으면 목록에서 AI 신호를 확인합니다. 그렇지 않으면 문의 상세에서 분석을 실행합니다.
4. 문의 상세에서 AI 요약과 답변 초안을 확인합니다.
5. 필요한 경우 답변 초안을 고객 답변 작성에 활용합니다.
6. 대시보드와 리포트에서 지원팀 운영 현황을 확인합니다.

## 한 줄 소개

SupportFlow는 AI가 문의 맥락을 정리해주고, 지원팀이 더 빠르게 우선순위를 판단하도록 돕는 고객지원 운영 대시보드입니다.

## 개발 및 운영

Next.js 16 / React 19 / TypeScript / Tailwind CSS / shadcn/ui를 사용합니다. 인증과 DB 접근은 Supabase, 서버 상태는 TanStack Query, 폼은 React Hook Form + Zod, 가벼운 UI 상태는 Zustand로 관리합니다.

현재 AI는 `AI_PROVIDER=mock`의 규칙 기반 데모 provider입니다. 실제 AI API 키 없이 분석·검토·초안 흐름을 사용할 수 있습니다. OpenAI provider는 아직 구현되지 않았습니다.

[설치, SQL 적용 순서, 권한 구조, AI 처리 흐름, 검증 및 문제 해결](docs/OPERATIONS.md)을 확인해 주세요. 새 앱을 실행하기 전에 보강 마이그레이션을 적용해야 합니다.

```bash
npm run lint
npm run typecheck
npm test
npm run test:db
npm run build
```

자동화는 현재 동작하는 규칙의 읽기 전용 화면이며, 연동 상태는 관리자용 설정 확인 화면입니다. 이메일·Slack·CRM 연결과 SLA 측정 엔진은 제공하지 않습니다. 문의 처리·리포트·AI 현황은 DB 데이터로 표시합니다.

### 관리자 사용자 관리

관리자 메뉴의 **사용자 관리**(`/admin/users`)에서 이름·이메일 검색, 역할 필터, 페이지 이동, 계정 추가와 역할 변경을 제공합니다. 일반 고객·상담원은 페이지와 `/api/admin/users` API에 접근할 수 없습니다.

- 계정 추가: 이름, 이메일, 12자 이상의 초기 비밀번호, 고객/상담원/관리자 역할을 지정합니다. Supabase Auth Admin API를 서버에서만 호출합니다. 초기 비밀번호는 저장하거나 목록에 표시하지 않으며, 안내 메일은 자동 발송하지 않습니다.
- 역할 변경: 확인 후 적용하며 DB에서 현재 관리자 권한을 다시 검사합니다. 본인의 역할은 바꿀 수 없습니다. 상담원에게 배정된 문의가 있으면 먼저 다른 상담원에게 이관해야 합니다(완료된 문의 포함).
- 이력: 계정 추가와 역할 변경을 `user_management_events`에 기록하고 관리자에게만 공개합니다. 역할 변경과 이력 저장은 하나의 트랜잭션입니다.
- 환경: 계정 추가에는 서버 전용 `SUPABASE_SERVICE_ROLE_KEY`가 필요합니다. 키가 없으면 계정 추가를 비활성화하고 기존 계정의 역할 관리는 유지합니다.
- DB: `supabase/migrations/20260906124838_admin_user_management.sql`을 기존 워크플로 강화 마이그레이션 다음에 적용합니다. `npm run test:db`에 권한 상승 방지와 변경 이력 검증이 포함됩니다.

역할을 바꾼 사용자가 이전 화면을 열어두고 있더라도 API와 RLS는 현재 DB 역할로 접근을 검사합니다. 새 메뉴를 보려면 페이지를 새로고침합니다.

### 고객 문의 화면

고객 계정은 로그인·회원가입 후 `/tickets/new`의 문의 작성 화면으로 이동합니다. 고객 전용 상단 메뉴는 **문의하기 / 내 문의**로 구성되며 운영 사이드바를 사용하지 않습니다. 문의 유형 선택, 제목·내용 검증, 접수 중 상태와 오류 안내를 제공하고 접수 후에는 내 문의에서 답변을 확인합니다. 고객의 `/dashboard` 접근은 문의 작성으로 연결하며 관리자 라우트 접근 제한과 기존 RLS를 유지합니다.

### 답변 완료 조건

`resolved`(답변 완료)는 마지막 공개 메시지가 지원팀 답변일 때만 허용합니다. 과거 답변 이후 새 고객 메시지가 오면 다시 답변해야 합니다. 공개 답변 등록과 자동 완료 처리는 기존 RPC의 하나의 트랜잭션에서 수행합니다. 내부 메모와 미전송 AI 초안은 완료 조건에 포함하지 않습니다. 화면에서 완료 선택을 비활성화하고 DB 트리거로 직접 상태 변경도 차단합니다. `20260906141930_require_public_reply_for_resolution.sql`은 기존의 공개 답변 없는 완료 건을 답변 대기로 보정하며, `ticket_logs`에 `resolution_corrected_without_reply` 시스템 이력(actor_id=null)을 남깁니다.

### 문의 일괄 배정

관리자는 문의함에서 현재 페이지의 여러 문의를 선택하고 **상담원 배정**으로 한 번에 배정하거나 이관할 수 있습니다. 필터·페이지 변경 시 선택을 해제합니다. 담당자 변경과 문의별 활동 기록은 하나의 트랜잭션으로 처리하며, 일부 문의가 삭제되거나 저장에 실패하면 전체 변경을 취소합니다. 답변 상태는 변경하지 않습니다.

### 상담원 전용 업무 범위

상담원은 로그인 후 **내 배정 문의**(`/tickets`)로 이동합니다. 목록·검색·상세·처리 통계·AI 검토는 현재 본인에게 배정된 문의만 대상으로 합니다. 관리자만 전체 조회와 배정·재배정을 할 수 있습니다. 미배정 문의나 다른 상담원의 문의는 직접 주소 또는 API로 조회해도 표시되지 않습니다. 고객에서 상담원으로 역할이 바뀐 계정의 과거 접수 문의도 배정 여부로 접근을 결정하며, 재배정 후 이전 상담원은 새 조회와 답변을 할 수 없습니다. 이미 열어둔 화면은 새로고침 시 현재 배정 상태가 반영됩니다.

### 고객 추가 메시지와 문의 재개

고객은 자신의 문의 상세에서 추가 메시지를 보낼 수 있습니다. 완료·종료된 문의도 답변 대기로 돌아가며 담당자는 유지합니다. 지원팀은 같은 대화에서 여러 번 답변할 수 있고 공개 답변을 보내면 다시 완료됩니다. 내부 메모는 상태를 바꾸지 않습니다. 메시지·상태·활동 기록은 하나의 트랜잭션으로 저장합니다. 작성 당시 역할과 메시지 순서를 별도로 저장해 역할 변경 이후에도 고객과 지원팀 발언을 구분합니다.

새 메시지는 앱 내 알림으로 안내하며, 활성 탭의 대화는 15초마다 갱신합니다. AI는 최초 문의와 최근 공개 대화 최대 20개를 분석합니다. 새 공개 메시지가 오면 재분석 후 초안을 사용할 수 있습니다.

### 앱 내 알림과 읽음 상태

- 상담원에게 신규 배정과 고객 추가 메시지를 알리고, 고객에게 지원팀 공개 답변을 알립니다. 미배정 문의의 고객 추가 메시지는 관리자에게 전달합니다. 내부 메모는 고객 알림을 만들지 않습니다.
- 헤더·사이드바의 **알림**에서 최근 50개를 확인합니다. 문의 목록에는 문의별 읽지 않은 알림 건수가 표시됩니다. 표시된 알림만 한 번에 읽음 처리할 수 있습니다.
- 문의 상세를 열면 실제로 표시된 메시지 순서까지 읽음 처리합니다. 그 이후 도착한 메시지는 읽지 않은 상태로 남습니다. 알림·문의 목록·대화는 활성 탭에서 15초마다, 창에 다시 포커스할 때 갱신합니다.
- 알림 수신자와 현재 문의 접근 권한을 DB에서 함께 검사합니다. 재배정·배정 해제 시 이전 상담원의 알림 접근을 차단하고 기존 미확인 알림을 정리합니다.
- 업무 변경과 알림 생성은 같은 트랜잭션입니다. 마이그레이션 적용 이후의 새 이벤트부터 알림이 생성됩니다. 이메일·브라우저 푸시 알림은 포함하지 않습니다.

### 최신 대화 기반 AI와 답변 임시 저장

AI 분석은 내부 메모를 제외한 최초 문의와 최근 공개 메시지 최대 20개를 대상으로 합니다. Mock 제공자는 마지막 고객 요청을 중심으로 분류하고 제공된 대화의 위험 신호도 검사합니다. 분석에 반영한 메시지 순서를 저장하며, 새 대화가 오면 **분석 업데이트 필요**를 표시합니다. 분석 도중 대화가 변경되면 저장을 거절하고, 오래된 분석의 승인·수정과 초안 입력을 제한합니다. 재분석이 완료되어도 고객에게 자동 전송하지 않습니다.

답변과 내부 메모는 계정·문의·공개 여부별로 이 브라우저의 localStorage에 7일간 임시 저장하고 재방문 시 복구합니다. 서버나 다른 기기에는 동기화하지 않습니다. 빈 내용과 전송에 성공한 내용은 삭제하고, 전송 실패 시에는 유지합니다. 브라우저가 저장을 차단하면 화면에 안내합니다. AI 초안을 복구해도 초안 사용 이력은 유지합니다.

### 응답 목표와 중복 전송 방지

응답 목표는 긴급 4시간·높음 8시간·보통 24시간·낮음 48시간이며 영업시간은 반영하지 않습니다. 목록과 상세에서 같은 계산으로 `35분 남음`, `2시간 10분 초과`를 표시하고 1분마다 갱신합니다. 최초 접수부터 대기 시간을 계산하며, 공개 답변 후 고객이 다시 질문하면 새 대기가 시작됩니다. 답변을 기다리는 동안 추가 메시지를 보내거나 담당자를 바꿔도 기존 대기 시작 시각은 유지됩니다. 완료·종료 후 수동으로 다시 열면 그 시점부터 계산합니다.

문의와 답변 등록은 계정별 요청 UUID를 사용합니다. 응답 손실 후 같은 요청을 재시도하면 DB가 기존 결과를 반환하여 문의·답변·알림·활동 기록의 중복 생성을 방지합니다. 같은 요청 번호로 다른 내용을 보내면 거절하고, 재시도 때도 현재 접근 권한을 검사합니다. 브라우저에는 요청 번호와 입력값의 SHA-256 해시만 보관합니다. 저장소가 차단된 환경에서는 페이지를 유지한 동안의 재시도만 동일 번호를 보장합니다. 기존 클라이언트와의 호환성을 위해 요청 번호 없는 호출은 일반 등록으로 처리됩니다.

### 문의·답변 첨부파일

- 고객의 최초 문의와 추가 메시지, 관리자·상담원의 공개 답변과 내부 메모에 같은 첨부 컴포넌트를 사용합니다. JPG·PNG·WebP·PDF를 파일당 3MB, 메시지당 최대 5개까지 첨부할 수 있습니다.
- 파일을 먼저 업로드하고 문의·답변 등록 트랜잭션에서 연결합니다. 실패한 업로드는 재시도하거나 제거할 수 있고, 연결 실패 시 메시지도 저장되지 않습니다. 중복 전송 방지 요청에는 첨부 ID 목록도 포함합니다.
- 업로드가 완료된 파일 선택은 현재 브라우저 탭의 sessionStorage에 보관하여 새로고침 후 재시도할 수 있습니다. 업로드 중이던 로컬 파일은 다시 선택해야 합니다. 미등록 파일은 24시간까지만 연결할 수 있으며, 이후 같은 사용자의 다음 업로드에서 정리를 시도합니다. 선택에서 제거한 미등록 파일도 삭제를 요청합니다.
- 비공개 `ticket-attachments` Storage 버킷을 사용합니다. 서버에서 로그인과 문의 접근 권한을 확인하고, 다운로드 시에도 고객 소유자·현재 담당 상담원·관리자 권한을 다시 검사합니다. 내부 메모 첨부는 고객에게 공개하지 않습니다. 서비스 역할 키는 서버에만 둡니다.
- 이미지는 대화에서 미리보기·확대가 가능하며, PDF는 다운로드로 제공합니다. 서버에서 파일 크기와 실제 파일 시그니처를 검사하고 SVG·HTML 등은 허용하지 않습니다. 다운로드 응답은 캐시하지 않습니다.
- 파일 업로드에는 `SUPABASE_SERVICE_ROLE_KEY`가 필요합니다. AI 분석은 텍스트 대화를 대상으로 하며 첨부 이미지/PDF 내용을 읽지는 않습니다.
